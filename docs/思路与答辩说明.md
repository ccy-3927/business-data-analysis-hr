# 分析思路与答辩说明

本项目把一家模拟企业的HR负责人作为分析使用者。管理问题依次是：离职案例集中在哪里、员工结构有什么差异、分类模型能提供多少辅助信息，以及有限访谈资源如何安排。

1. 先核对附件A，选取明确对应的IBM HR，而不是只因为某个平台被列出就任选其他数据。
2. 官方接口下载原文件，记录哈希、版本和许可；说明虚构数据来源。
3. 审计缺失、重复、字段类型、常量和工龄逻辑。没有问题的记录保留，不人为制造“清洗成果”。
4. ABC分析岗位案例贡献，K-Means识别结构，预测模型比较排序与误报漏报。三者回答不同问题。
5. 把教材十种图形迁移为Python图形，加十四张模型图及联动大屏。
6. 把结果变成有负责人、周期与指标的访谈和员工支持方案，最后做运行、数字、排版核验。

常见答辩问题：

- 为什么不是年度离职率？原始文件没有日期和期间，只能计算样本中的标签比例。
- 为什么模型准确率不高仍有意义？低阈值提高召回，也带来误报；常数模型准确率高却无法识别正类。主要用AP/AUC评价排序，并报告资源代价。
- 阈值是否偷看测试集？没有。先隔离测试集，模型和阈值仅在训练期通过五折结果确定。
- 聚类是否泄漏？聚类是全样本描述，不含离职标签，也不把群体标签输入预测模型。
- 为什么用ABC？它衡量各岗位贡献的离职案例数量，帮助分配调查工作量；同时看岗位内比例，避免仅按人数规模判断风险。
- 虚构数据有什么业务价值？用于构建完整模拟企业决策流程，但不能据此声称IBM真实经营结论或承诺干预收益。
- 为什么做不到自动留人？目前只有关联与标签分类，没有真实干预试验。建议需要经明确周期和对照评估检验。
